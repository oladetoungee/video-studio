What the first digit of an HTTP status code tells you

A 4 means check the request. A 5 means check the server.

01 / 10
Every response carries a three-digit status code
HTTP/1.1 200status code OKreason phrase

The code tells you what happened, and the body gives you the detail. You can already tell a lot from the first digit.

Which redirect? 301, 302, 307 or 308
Permanent
Temporary
May switch POST to GET
301Moved for good
302Back soon
Keeps POST as POST
308Moved for good
307Back soon

For normal web pages, 301 and 302 are fine. If you're redirecting an API where POST requests matter, I would use 307 and 308.

05 / 10
400 or 422?
400
Bad Request
Broken JSON, like a missing bracket
422
Unprocessable Content
The data inside makes no sense, like a book with no title

Some APIs send 400 for validation errors too. I think 422 is clearer, because it tells the front end the format was fine and the data needs fixing.

07 / 10
401 asks who you are. 403 says you can't do this
401
Unauthorized
No hotel keycard at all, or the card doesn't work
403
Forbidden
Your card works fine, but it's for another room

On a 401, send the user to log in. On a 403, logging in again with the same account won't help.

08 / 10
Your app sends 500. The proxy sends 502 and 504
500
Internal Server Error
Usually an uncaught exception
502
Bad Gateway
The proxy got an invalid answer from your app
504
Gateway Timeout
Your app took too long, like a slow query
09 / 10
Never send
200 OK when something failed

Your front end only sees the 200, and your monitoring counts it as a success. Send the real code and put the detail in the body.
