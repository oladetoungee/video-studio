Overview

CVE-2026-109618 is a critical remote code execution (RCE) vulnerability affecting all PHP versions from PHP 5 onward. The CVE was reserved and first surfaced publicly around October 20, 2026, when details were reportedly leaked ahead of an embargo, prompting PHP maintainers to announce emergency patches were imminent. The vulnerability is estimated to carry a HIGH/Critical CVSS severity, with some sources citing a score of 9.2 (BleepingComputer, Cryptika). It is closely related to a companion vulnerability, CVE-2026-109619, and the pair has been dubbed "PHP2Shell" by the security community (Huntress, SecurityWeek).

Technical details

CVE-2026-109618 is a remote code execution flaw rooted in PHP core, affecting all versions from PHP 5 onward. An unauthenticated attacker can exploit this vulnerability over the network to execute arbitrary code on the affected server with the privileges of the web server process. The precise root cause (CWE classification) and specific vulnerable code path have not been fully disclosed publicly, as the vulnerability was leaked ahead of the official patch release and technical details remain limited pending the official advisory (watchTowr, Sansec, ThreatLandscape). No public proof-of-concept exploit code has been confirmed at the time of initial disclosure (Feedly).

Impact

Successful exploitation allows an unauthenticated remote attacker to execute arbitrary code on any PHP server running PHP 5 or later, with the privileges of the web server process. Given PHP's ubiquity in web infrastructure — powering a significant portion of the internet — the potential attack surface is enormous, affecting web applications, CMS platforms, e-commerce systems, and APIs worldwide. Exploitation could lead to full server compromise, data exfiltration, web shell deployment, lateral movement within internal networks, and supply chain attacks against hosted applications (SecurityWeek, TheHackerNews, Qualys Blog).

Exploitability

At the time of initial disclosure, no confirmed public proof-of-concept exploit code existed and no in-the-wild exploitation had been observed (Feedly). However, the premature leak of vulnerability details ahead of the official patch significantly increased the risk of rapid weaponization, with SecurityWeek warning that mass exploitation was looming (SecurityWeek). The CVE status remains "Reserved" and no EPSS score or CISA KEV catalog entry has been confirmed at this stage. The vulnerability's unauthenticated, network-exploitable nature and the breadth of affected PHP versions make it a high-priority target for threat actors (Aikido, CERT-EU).

Mitigation and workarounds

Official patches had not been released at the time of initial disclosure, but PHP maintainers announced emergency security releases were imminent (BleepingComputer). Organizations should immediately monitor the official PHP security announcements and apply patches as soon as they become available for all supported PHP branches. In the interim, recommended mitigations include implementing network access controls to restrict external connections to PHP services, disabling unnecessary PHP functions that could facilitate RCE (e.g., exec, shell_exec, system, passthru), deploying a Web Application Firewall (WAF) to detect and block exploitation attempts, and ensuring PHP processes run with minimal required privileges (Feedly, CERT-EU, ASD ACSC).

Community reactions

The vulnerability generated significant community attention due to the unusual circumstance of details leaking ahead of the official embargo, with PHP maintainers publicly warning administrators to prepare for emergency patches (BleepingComputer, Ars Technica). Security researcher Kevin Beaumont (GossiTheDog) commented on the situation via Mastodon, and the topic trended on Hacker News and Reddit's r/sysadmin (Cyberplace Social, Reddit). CERT-EU and the Australian Cyber Security Centre (ACSC) both issued advisories urging immediate action (CERT-EU, ASD ACSC). SecurityWeek warned of looming mass exploitation, and multiple security vendors including Huntress, Qualys, Aikido, and Sansec published rapid-response analyses under the "PHP2Shell" moniker (SecurityWeek, Huntress).
