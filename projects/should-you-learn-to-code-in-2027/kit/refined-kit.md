Someone I know really wants to be a software developer right now, and I was thinking about the advice to give them. When I started, I thought it was so hard, but looking back, it was so easy. So I have been thinking about what I would actually tell a beginner who wants real software development skills, and doesn't only want AI to write the code for them. I would say yes, learn, but not the same way people learned three or four years ago. I would tell them to focus on four things.

The first is reading code. AI writes a lot of the code now. At my job I barely write code by hand anymore, and what I do is understand the code and monitor what it is doing. A lot of people writing code with AI are not even reading it, and I think reading it is very important, because it is how you tell what the AI wrote and whether it is what you asked for. A lot of code will be written, and you need to know how to read it in case you need to.

The second is debugging, which means finding out why something is broken. Say a user signs up on your app and it crashes with an error. AI is really good at debugging too, but it doesn't always understand the context. If you paste that error into a model that isn't so solid and say "fix this", one easy fix is to wrap the save in a try-catch. The crash goes away, but the user still is not signed up, and nobody can tell them why. If you can read the error yourself, you see that someone with that email already has an account, and the database refused to save a second one. The real fix checks for that and tells the user the email is already taken. When you use AI to code, you are the human in the loop, and debugging is how you know whether the fix AI gives you is for the actual problem.

The third is the fundamentals and a little bit of system design. The fundamentals are how the web works underneath, like what happens when you send a request and how a database saves your data. System design is how the parts of your app work together and what can go wrong between them. When a customer pays for an order on an online shop, the payment provider sends your server a message called a webhook to say the payment was successful. Many providers send it again if your server does not reply in time. Paystack, for example, says in its docs that it keeps retrying for 72 hours until it gets a 200 OK. If your code is not ready for that, you could record the payment twice or send the customer's order twice.

The fourth is domain knowledge, which means understanding the area your software is for. I write code for a fleet management company, and other people write code for finance, health, payments, logistics or schools. If you build a stock app for a pharmacy, AI can write it quickly, but a pharmacy needs to sell the medicine that expires first and know which batch each product came from. If you have the domain knowledge, you ask AI to build it and still notice what is missing. This is a big part of why every company has a few engineers everybody goes to, because they know the business really well. When I got my first job, my manager would often send my work back and say I could not do it that way, because he had context I did not have yet.

Build with AI first, learn to work with it, and then learn the rest: reading code, reading other people's code, debugging, the fundamentals and a little bit of system design. There are so many free, reliable places to learn, like MDN Web Docs, freeCodeCamp, The Odin Project and Harvard's CS50, and the System Design Primer on GitHub for system design. Commit to it, because the learning itself is so good for you. Just understand the market and the impact AI has had on it.
