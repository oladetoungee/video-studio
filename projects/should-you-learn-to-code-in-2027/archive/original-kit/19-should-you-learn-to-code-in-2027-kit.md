If you want to get into software development right now, the reality is that junior developer job postings have become very, very rare.

Someone I know is really, really interested in being a software developer right now.

And I don't even know the advice to give them.

Even then, I was thinking it was so difficult.

But it was so easy to come into the field then.

Reading code, debugging, fundamentals with a bit of system design, and domain knowledge.

**[SEGMENT 3: READING CODE]**

The first skill that matters now is reading code.

AI will do a lot of the code writing for you.

I'm not joking, we are using AI to write code, I promise you.

At my job, I barely write code by hand anymore.

What I do is understand the code, and monitor what it's doing.

And people write so much code with AI these days that a lot of the people writing the code are not even reading it as much anymore.

But I would say reading code is still very, very important.

Reading code means you can look at what the AI wrote and tell what it does, and whether it's what you asked for.

And it's interesting, because you also have to write code to be able to read code.

So I would recommend it as a skill for anyone that is starting to build a career in software development.

---

**[SEGMENT 4: DEBUGGING]**

**[~3:00 BEAT: a real bug, and an AI "fix" that only hides it, are coming]**

The second skill that matters now more than ever is debugging.

Debugging means finding out why something is broken.

So say a user signs up on your app, and the app crashes with this error.

**[CODE ON SCREEN]**
```
ERROR 1062 (23000): Duplicate entry 'ada@example.com' for key 'users.email'
```

AI is really good at this, and I'm not even joking.

But it doesn't always understand the context.

For example, if I paste this into AI, maybe a model that is not so solid, and I say "fix it," one easy fix it might give is to wrap the save in a try-catch.

So the error is caught, and the crash goes away.

**[CODE ON SCREEN]**
```js
// the "fix" that only hides the problem
try {
  await db.users.create({ email, password });
} catch (error) {
  // error swallowed. no crash, and no account either
}
```

The page stops crashing.

But the user still isn't signed up, and nobody can tell them why.

But if you can read the error yourself, you can come to the conclusion that someone with this email already has an account, and the database is refusing to save a second one.

So the real fix is to actually check for that, and tell the user that the email is already taken.

**[CODE ON SCREEN]**
```js
// the real fix
const existing = await db.users.findByEmail(email);

if (existing) {
  return res.status(409).json({ message: "This email is already taken." });
}

await db.users.create({ email, password });
```

So debugging is a skill that gives you that bandwidth.

When you use AI to code, you're the human in the loop, the person who checks what it does.

So as the human in the loop of using AI to code, you need that.

AI can really help with a lot of that already.

But you have to know enough to understand when a fix that AI gives you only hides the actual problem, right?

---

**[SEGMENT 5: FUNDAMENTALS AND A BIT OF SYSTEM DESIGN]**

The third skill that matters now is the fundamentals, and a bit of system design.

Fundamentals are about how the web works, all the stuff underneath.

Like what happens when you send a request, and how a database saves your data.

System design is thinking about how all the parts of your app work together, and what can go wrong between them.

For example, where is your user data being saved?

And how does it connect to what the user sees?

This is a real example from payments.

When a customer pays for an order on an online shop, the payment provider sends your server a message to say the payment was successful.

That message is called a webhook.

Many providers will send that webhook again if your server doesn't reply in time.

So your app can receive the same "payment successful" message twice.

Your code has to be ready for that.

Or else you could record a payment twice, or send the customer two orders, right?

**[CODE ON SCREEN]**
```js
app.post("/webhooks/payment", async (req, res) => {
  const { reference } = req.body;

  // seen this payment before? then do nothing
  const alreadySaved = await db.payments.findByReference(reference);
  if (alreadySaved) {
    return res.sendStatus(200);
  }

  await db.payments.create({ reference, status: "paid" });
  await createOrder(reference);

  res.sendStatus(200);
});
```

So you need knowledge of these fundamentals.

**[SEGMENT 6: DOMAIN KNOWLEDGE]**

**[~6:00 BEAT: the last skill, with the pharmacy example and your manager story still to come]**

The fourth skill that matters more now is domain knowledge.

That means understanding the area that your software is for.

For example, I write code for a fleet management company.

Some people write code in finance, or in health, or in payments, or in logistics, or for schools.

So say you're building a stock app for a pharmacy, right?

AI can write a stock app very quickly.

But a pharmacy needs to sell the medicine that expires first, before the newer stock.

And it needs to know which batch a product came from.

**[ON SCREEN: Pharmacy stock app. Sell what expires first. Track which batch each product came from]**

If you have that domain knowledge, you will ask your AI to build it in.

And you will notice when it's missing.

But if you don't know it, you're still able to build your app with AI, but the app is still not solid for the pharmacy.

So whatever field you're in, you need to establish domain knowledge in that field.

It's the reason why in companies, there will always be some engineers that everybody goes to.

Some companies call them staff engineers.

A big part of what makes them so valuable is that they know the business really well.

When I first got my job, I would do some things, and I remember my manager would always refer me back and say, oh yeah, no, you cannot do that.

Because he had more context, right?

So this is also part of domain knowledge that you have to build.

**[SEGMENT 7: SHOULD YOU STILL LEARN TO CODE IN 2027?]**

So should you still learn to code in 2027?

I still think you should try to learn how to code.

I just don't think you should think of it as something that should give you a junior developer role.

I don't think you should put so much trust in that right now.

So try to learn how to build with AI first.

Learn to work with it first.

And then start to learn the rest, reading code, reading other people's code, debugging, the fundamentals, and a little bit of system design.

There are a lot of free, reliable places to learn from, and I'll just show them on the screen.

**[ON SCREEN: Free places to learn. MDN Web Docs (developer.mozilla.org). freeCodeCamp (freecodecamp.org). The Odin Project (theodinproject.com). Harvard's CS50 (cs50.harvard.edu, free)]**

There are also a lot of free, reliable places to learn system design.

**[ON SCREEN: Free system design. The System Design Primer, free on GitHub (github.com/donnemartin/system-design-primer)]**

I think you should actually commit to doing this.

It helps so much.

But you also need to understand the reality of the market, and the impact that AI has had on the market as well.

So if anybody's telling you that if you learn how to code now, you'll get a junior software developer role, you have to think about it very well.

Because I'm not sure that is a promise you can hold on to, at least in this age and time.

### Title:
> Should You Still Learn to Code in 2027?

### SEO Title:

---

If you want to get into software development right now, the reality is that junior developer job postings have become very rare. Indeed's research team, Hiring Lab, published a report in July 2026 by Felix Aidala and Sneha Puri on how the job market is tilting toward seniority. In the first quarter of 2026, only 4.5 percent of software development postings on Indeed were entry level, the smallest share of any sector they looked at, while 69.3 percent were senior. Developer postings have gone up. Indeed found US software development postings rose almost 15 percent between February 2025 and June 2026, but senior roles made up 71 percent of the increase from May 2025 to May 2026.

Someone I know really wants to be a software developer right now, and I didn't know what advice to give them. When I started, I thought it was so difficult, but looking back, the door was wide open. So I have been thinking about what I would actually tell a beginner who wants real software development skills, and doesn't only want to vibe code, which is when you describe what you want and let AI write the code without really reading it. I would tell them to focus on four things.

The first is reading code. AI does a lot of the code writing now. At my job I barely write code by hand anymore, and what I do is understand the code and monitor what it is doing. A lot of people writing code with AI are not even reading it as much anymore, and I think reading it is still very important, because it is how you tell what the AI wrote and whether it is what you asked for. You also have to write some code yourself to get good at reading it.

The second is debugging, which means finding out why something is broken. Say a user signs up on your app and it crashes with a duplicate entry error. If you paste that into a weak AI model and say "fix it," one easy fix is to wrap the save in a try-catch. The crash goes away, but the user still is not signed up, and nobody tells them why. If you can read the error yourself, you see that someone with that email already has an account, and the database refused to save a second one. The real fix checks for that and tells the user the email is taken. When you code with AI, you are the human in the loop, the person who checks what it does, and debugging is how you notice when a fix only hides the problem.

The third is the fundamentals and a bit of system design. The fundamentals are how the web works underneath, like what happens when you send a request and how a database saves your data. System design is how the parts of your app work together and what can go wrong between them. When a customer pays for an order on an online shop, the payment provider sends your server a message called a webhook to say the payment was successful. Many providers send it again if your server does not reply in time. Paystack, for example, says in its docs that it keeps retrying for 72 hours until it gets a 200 OK. If your code is not ready for that, you could record the payment twice or send the customer two orders.

The fourth is domain knowledge, which means understanding the area your software is for. I write code for a fleet management company, and other people write code for finance, health, payments, logistics or schools. If you build a stock app for a pharmacy, AI can write it quickly, but a pharmacy needs to sell the medicine that expires first and know which batch each product came from. If you know that, you ask for it and notice when it is missing. This is a big part of why companies value their most senior engineers, sometimes called staff engineers, because they know the business really well. When I got my first job, my manager would often send my work back and say I could not do it that way, because he had context I did not have yet.

So should you still learn to code in 2027? I think you should. I would learn to build with AI first, then move into reading code, reading other people's code, debugging, the fundamentals and a little system design. There are good free places to learn, like MDN Web Docs, freeCodeCamp, The Odin Project and Harvard's CS50, and the System Design Primer on GitHub for system design. Commit to it, because it helps so much. Just understand the market and what AI has done to it. If anybody tells you that learning to code now will get you a junior developer role, think about it very well, because I am not sure that is a promise you can hold on to, at least in this age and time.
