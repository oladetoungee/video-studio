03 / 08
Finding Bob in
a million rows
Simplified, after S. Egorenkov.

3 hops down the tree instead of 1,000,000 row checks.

04 / 08
Adding one is
one line
SQL
CREATE INDEX idx_orders_email
ON orders (customer_email);
Laravel migration
$table->index('customer_email');
Live table? Add CONCURRENTLY (Postgres).

Now the database checks the index first, then goes straight to Bob's order.

05 / 08
Check it's
actually used

Put EXPLAIN in front of your query.

PostgreSQL, before (simplified)
EXPLAIN SELECT * FROM orders
WHERE customer_email = 'bob@…';
Seq Scan on orders
Reading every row.
after CREATE INDEX
Index Scan using idx_orders_email
Using your index. (Bitmap Index Scan too.)
Tiny tables may still show Seq Scan. MySQL: ALL = full scan; ref = index.
06 / 08
Don't index
every column
01
Slower writes
Every insert updates every index. 1 row + 6 indexes = 7 writes.
02
More storage
Each index is extra data on disk.
03
Tiny tables don't need one
With about 10 rows, the database just scans.

Index the columns you search, join or sort by.
